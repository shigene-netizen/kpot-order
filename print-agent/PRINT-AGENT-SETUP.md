# 厨房自动打单 —— 安装说明（Windows）

员工在厨房看板上点 **PREPARING**，厨房打印机就吐出一张厨房单。
这份说明带你从零装好，大约 15 分钟，只需要做一次。

---

## 它是怎么连起来的（先看懂这张图，后面就不容易懵）

```
[手机/平板: 员工点 PREPARING]
        ↓   （互联网）
[云端的 server.js]  ← 把「厨房单」排进打印队列，落盘保存，不怕重启
        ↓   （互联网）
[店里那台常开的 Windows 电脑]  ← 每隔 2 秒来问一次「有单子吗？」
        ↓   （店内局域网，TCP 9100）
[网口 / WiFi 热敏打印机]  ← 吐出厨房单

        ┌── 这台电脑怎么知道云端的地址？（每次发布都会换）
        └→ [GitHub Pages 转发页]  ← 永远不变的地址，上面写着当前网站地址
```

**关键一点**：打印机在你店里的局域网上，互联网**够不着它**。
所以必须有一台店内的电脑去「取单 → 交给打印机」。
那台电脑上跑的小程序就是 `print-agent`。

> 为什么要这样绕一圈？因为云端服务器根本看不见你店里的打印机。
> 让店内电脑主动去「取」，就不用在路由器上开端口、不用固定公网 IP。

---

## 需要准备什么

| 东西 | 要求 |
|---|---|
| 热敏收据打印机 | 带**网口**或 **WiFi**，支持 ESC/POS（绝大多数收据打印机都是） |
| 一台电脑 | Windows，**营业期间一直开着**（不用关机、不用关屏幕，但**必须联网**） |
| 路由器 | 打印机和这台电脑要连**同一个**店内网络 |

> 打印机是 USB 的怎么办？先把打印机接到那台电脑上，用打印机厂商的工具
> 把它设成「网络打印机 / 共享」，或者换一台网口机型。本方案只走网络。

---

## 第一步：让打印机连上网，并记下它的 IP

1. 按打印机说明书把它连到店内 WiFi，或用网线插到路由器。
2. 打印一张**自检页**（通常：关机 → 按住 FEED 键 → 开机），自检页上会印出
   它的 IP，形如 `192.168.1.50`。
3. 也可以进打印机设置工具 / 路由器后台找它的 IP。

**把 IP 写在纸上。** 后面要用。建议顺便在路由器里给它**绑定固定 IP**
（DHCP 保留），否则路由器重启后 IP 可能变，打印就断了。

> ⚠️ 常见坑：IP 是会变的。如果你发现某天突然不打了，**第一件事就是
> 重新打印自检页核对 IP**。

---

## 第二步：在这台电脑上装 Node.js

1. 打开 <https://nodejs.org>
2. 点那个大的绿色 **LTS** 按钮下载。
3. 一路 **Next** 装完（默认选项就行，不用改）。

装完不用做任何配置。

> 这个程序**不需要 `npm install`**，它只用 Node 自带的功能。
> 所以不会出现「装依赖装不上」这类问题。

---

## 第三步：填 config.json

1. 进到 `print-agent` 文件夹。
2. 把 `config.example.json` **复制一份**，改名成 `config.json`。
3. 用记事本打开 `config.json`，**其实只需要填打印机 IP**：

```json
{
  "discoveryUrl": "https://shigene-netizen.github.io/kpot/target.js",
  "discoveryMinutes": 5,

  "serverUrl": "",
  "printKey": "",
  "printerHost": "192.168.1.50",
  "printerPort": 9100,
  "pollSeconds": 2
}
```

| 字段 | 填什么 |
|---|---|
| `printerHost` | 第一步记下的打印机 IP，例如 `192.168.1.50`。**填数字，不要填 `EPSON123` 这种名字。** |
| `printerPort` | 绝大多数网络收据打印机是 `9100`，不要改。 |
| `printKey` | 一般**留空**。见下面「关于 printKey」。 |
| `pollSeconds` | 隔几秒问一次服务器。`2` 就很好。调小只是感觉快一点，**不会真的打得更快**。 |
| `discoveryUrl` | **不要动。** 网站地址是从这里自动查的，见下。 |
| `discoveryMinutes` | 隔几分钟重新查一次地址。`5` 就很好。 |
| `serverUrl` | **留空**。只有自动查询失败时才会用它当后备。 |

### 为什么不用填网站地址（这一版新加的）

点餐网站**每次重新发布都会换一个新地址**。老版本要求把地址写进 `config.json`，
结果就是：**每次发布完都得跑到店里那台电脑上改一次文件**——忘了改，打印就
**静默停摆**（看板上只会显示「代理很久没连上」，没人知道是地址变了）。

现在改成**自动查**：

- 店里印的二维码本来就指向一个**永远不变**的转发页（GitHub Pages）；
- 那个转发页上写着网站的当前地址；
- 这个程序去那儿读，**每 5 分钟重读一次**；
- 而且只要发现**连不上了、或者服务器回 400**（重新发布后旧地址就是这个反应），
  **立刻**重新查一次，不等那 5 分钟。

**所以发布完什么都不用做**，几分钟内它自己就换到新地址了。

> 那 `discoveryUrl` 什么时候要改？只有**转发页本身搬家**时（换 GitHub 账号、
> 换仓库名）。那种事很少发生。

> 想固定死一个地址？把 `discoveryUrl` 填 `""`，再把 `serverUrl` 填上网站地址。
> 这样就是老行为，发布后需要自己改。

## 第四步：双击 start.bat

双击 `print-agent` 里的 **`start.bat`**，会弹出一个黑窗口：

```
  KPOT To Go — kitchen print agent
  --------------------------------
  printer : 192.168.1.50:9100
  poll    : every 2s
  key     : none (server must also have none)
  address : looked up automatically every 5 min
            from https://shigene-netizen.github.io/kpot/target.js

  Leave this window open. Tickets print automatically.
  Press Ctrl+C to stop.

  -> https://你的网站当前地址
  [14:03:53] connected. 0 ticket(s) waiting.
```

**看到 `connected.` 就说明它连上了。** 窗口**别关**，关了就不打单了。

`-> ` 那一行是它**自动查到的网站地址**。网站重新发布后，这里会自己变成新地址，
并打印一行 `the app has moved to … — following it`。**看到这行是正常的**，
说明自愈生效了，不需要你做任何事。

> 如果显示 `cannot reach the server yet`，见下面「出问题了怎么办」。
> 如果显示 `the server rejected the print key`，说明 `printKey` 填错了。

---

## 第五步（重要）：设置开机自动启动

黑窗口一旦被关掉、或电脑重启，打印就停了。所以一定要设成自动启动：

1. 按 `Win` 键，搜索 **「任务计划程序」**，打开。
2. 右边点 **「创建任务」**（不是「创建基本任务」）。
3. **常规** 选项卡：
   - 名称：`KPOT 厨房打印`
   - 勾选 **「不管用户是否登录都要运行」**
   - 勾选 **「使用最高权限运行」**
   - 配置：`Windows 10`（或你的系统）
4. **触发器** 选项卡 → 新建：
   - 开始任务：**「登录时」**（如果选了「不管用户是否登录都要运行」，这里选**「启动时」**）
   - 确定
5. **操作** 选项卡 → 新建：
   - 操作：**「启动程序」**
   - 程序或脚本：填 `start.bat` 的完整路径，例如
     `C:\kpot\print-agent\start.bat`
   - 起始于（重要，别留空）：`C:\kpot\print-agent`
6. **设置** 选项卡：
   - 取消勾选 **「如果任务运行时间超过以下时间，停止任务」**
   - 勾选 **「如果任务失败，按以下频率重新启动」**，间隔 `1 分钟`，尝试 `3` 次
7. 确定，输入这台电脑的 Windows 密码（如果要求）。

重启一次电脑，确认黑窗口自己起来了。

## 怎么知道它活着？（不用跑到厨房去看）

打开**厨房看板**（`/admin-orders.html`），订单列表上方有一行小字：

| 显示 | 意思 | 该做什么 |
|---|---|---|
| 🟢 `Printer ready · agent checked in 3s ago.` | 一切正常 | 什么都不用做 |
| 🟡 `3 ticket(s) waiting to print…` | 排到队了但还没打出去 | 等一下；一直不动就看下一行 |
| 🔴 `No print agent has ever connected…` | **那台电脑上的程序没在跑** | 去电脑上双击 `start.bat`，或检查开机自启 |
| 🔴 `Print agent last checked in 5 min ago…` | 电脑睡了 / 断网了 / 窗口被关了 | 检查电脑和网络 |
| 🔴 `N ticket(s) failed to print — <原因>` | 打印机没吃下纸。**原因会写在红条里**，末尾就是它试的地址 | 检查打印机电源、纸；拿红条里的地址跟打印机自检页对一下 IP；然后按订单上的 **Reprint** |

订单卡片上每张单也有打印标记：

| 标记 | 含义 |
|---|---|
| 🖨️ `QUEUED` | 已排进队列，等电脑来取 |
| 🖨️ `PRINTING…` | 电脑正在打 |
| 🖨️ `PRINTED` | 打好了 |
| 🖨️ `REPRINTED` | 这是补打的 |
| 🖨️ `PRINT FAILED` | **没打出来**，需要处理 |

**没打出来一定要处理**——厨房看不到单子，等于没收到这张订单。
纸用完了、卡纸了，都可以在看板上点 **🖨️ Reprint** 重新打一张。

## 关于 printKey（安全）

`printKey` 是用来防止**别人冒充你的电脑来取单**的。

- 默认**不设**也能用（`printKey` 留空，服务器上也没配），因为订单内容本身
  不含支付卡信息。
- 想更安全就在服务器上设一个：
  - 服务器读的是环境变量 `PRINT_KEY`，或者 `secrets.local.json` 里的 `printKey`。
  - 设了之后，**这台电脑的 `config.json` 里 `printKey` 必须填一模一样的值**。
- 服务器**没有**单独配 `printKey` 时，会退而使用 **admin key**。
  也就是说：如果你设了 admin key 但没设 printKey，那么这里的 `printKey`
  要填 **admin key 的值**。

> 拿不准就先留空试一次，能打出来说明当前是「没设钥匙」的状态。

## 出问题了怎么办

按这个顺序排查，基本都能自己解决：

| 现象 | 最可能的原因 | 怎么办 |
|---|---|---|
| 黑窗口说 `cannot reach the server yet` | 电脑断网 | 检查这台电脑能不能上网。地址是自动查的，一般不用管 |
| 黑窗口说 `address lookup failed` 或 `returned HTTP` | 这台电脑连不上转发页（断网 / 被防火墙挡） | 先用浏览器打开 `discoveryUrl` 看能不能开。**它不会因此停止打印**——会继续用当前已知的地址 |
| 黑窗口说 `the server answered 400` | 网站重新发布了，旧地址失效 | **正常，不用管。** 它会自己重新查地址并换过去，下一行会打印 `the app has moved to …` |
| 黑窗口一直停在 `could not work out the app's address yet` | 转发页也连不上，且 `serverUrl` 是空的 | 检查网络；实在不行就把 `serverUrl` 填上当前网站地址当后备 |
| 黑窗口说 `server rejected the print key` | `printKey` 和服务器不一致 | 两边改成一样，或都留空 |
| 窗口显示 `FAILED to print ... printer refused the connection` | 打印机没开 / IP 变了 / 不在同一网络 | 开打印机、重新核对自检页上的 IP。**报错末尾会写明它试的地址**（`— tried 192.168.1.50:9100`），照那个地址去查 |
| 窗口显示 `FAILED to print ... timed out after 0/965 bytes` | **连接根本没建立**（不是「拒绝」）：打印机 IP 变了 / 打印机没开 / 不在同一网段 | 同上。**报错末尾就是它试的地址**，拿它跟打印机自检页上的当前 IP 对一下 |
| 看板显示 `No print agent has ever connected` | 程序没跑 | 双击 `start.bat`；检查开机自启设好没有 |
| 有单子但打印机不动 | 纸装反了 / 纸用完 / 卡纸 / 盖子没盖 | 检查纸仓，按 FEED 键试走纸 |
| 打出乱码 | 打印机不支持 ESC/POS 或纸张宽度选错 | 见下面「纸宽设置」 |
| 偶尔重复打同一张 | 网络抖动导致「打好了」的回报没送到，服务器重发 | 偶发一两张可接受；频繁发生要查网络 |

## 纸宽设置（打出来字太大 / 溢出）

在**服务器的** `assets/config.js` 里改，改完重新发布：

```js
printer: {
  enabled: true,
  paper: '80',   // '80' = 80mm 纸（48 字符宽，厨房常用）
                 // '58' = 58mm 纸（32 字符宽，手持小票机）
  cut: true      // true = 打完自动切纸；没有切刀的老机器改成 false
}
```

- 字太大、一行放不下 → 大概率纸宽选错了。
- 打不出「切纸」动作 → 你的机器没有切刀，把 `cut` 改成 `false`。
- 想临时**完全停掉打单** → 把 `enabled` 改成 `false`，看板就不再显示打印状态。

> 注意：打印机的**地址**不在这个文件里，它在店里那台电脑的
> `print-agent/config.json` 里。原因很简单——这个文件跑在云端，
> 它够不着你店里的打印机。

## 两个要理解清楚的地方（免得误会）

**1. `PRINTED` 的意思是「字节已经全部发出去了」，不是「机器确认纸出来了」。**

网络打印机（9100 端口）几乎不给你回话：它收下数据就关连接，
**没有「打印成功」这种回复**。所以这里的判定是：

- 写到一半就断 → 算失败，会重试；
- 全部写完 → 算成功。

如果把「写完但没收到确认」当成失败，服务器就会重发，
**厨房会拿到两张一样的单子**——那比偶尔漏报一次更难处理。

**2. 排队是「租借」式的，电脑崩了不会把单子弄丢。**

电脑取走一张单 → 租借 2 分钟 → 打完回报。
如果电脑在这 2 分钟内崩了，租借到期，单子**自动回到队列**，
换一台电脑（或重启后）还能打出来。

## 技术细节（给维护的人）

| 项目 | 说明 |
|---|---|
| 程序位置 | `print-agent/agent.js`（约 270 行，零依赖，只用 Node 内置模块） |
| 为什么不用 `fetch` | 老版本 Node 没有 `fetch`。店里电脑装什么版本说不准，所以用内置 `http`/`https`。 |
| 打印机协议 | 裸 TCP 9100，发 ESC/POS 字节 |
| 票据在哪生成 | **服务器**（`printer.js`）。这台电脑只搬字节，所以改票据版式不用碰店里这台机器。 |
| 排队文件 | 服务器上的 `print.local.json`（重启不丢；已 gitignore） |
| 相关接口 | `GET /api/print/jobs`、`POST /api/print/jobs/:id/ack`、`GET /api/print/status`、`POST /api/orders/:id/reprint` |
| 票据版式 | `printer.js`：`buildTicket` 出「样式指令」，再分别渲染成 ESC/POS 字节或纯文本预览。**一份版式两个后端**，所以后台看到的预览和真打出来的不会走样。 |
| 地址发现 | `parseTargetJs()` 从转发页的 `target.js` 里读 `baseUrl`。**先剥注释再匹配**——不然「注释掉旧地址、粘上新地址」这种最自然的改法会让它悄悄跟着**旧地址**跑。 |
| 什么时候重查地址 | 每 `discoveryMinutes` 一次；**另外**一旦收到 400（重新发布后旧地址的反应）或连接失败，**立刻**重查，不等周期。 |
| 查不到地址时 | **绝不清掉正在用的地址**。转发页抽风不是停止打印的理由。 |
| 测试 | `_dev/test_printer.js`（版式逐字节）、`_dev/probe_print_flow.js`（真服务端+真代理+假打印机）、`_dev/probe_board_print_ui.js`（真浏览器看板）、`_dev/test_agent_discovery.js`（换地址后能不能自己跟过去）、`_dev/fake_printer.js`（假打印机） |
| 环境变量覆盖 | `KPOT_SERVER_URL`、`KPOT_DISCOVERY_URL`、`KPOT_DISCOVERY_MS`、`KPOT_DISCOVERY_MINUTES`、`KPOT_PRINT_KEY`、`KPOT_PRINTER_HOST`、`KPOT_PRINTER_PORT`、`KPOT_POLL_MS`、`KPOT_PRINT_TIMEOUT`（环境变量优先于 config.json，测试用） |
| ⚠️ 空值陷阱 | `KPOT_DISCOVERY_URL=''` 是**真的关掉**自动查地址（用 `hasOwnProperty` 判断，不是 `||`）。别的测试靠这一条保持不联网。 |
